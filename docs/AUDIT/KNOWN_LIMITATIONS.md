# LeakCheck Known Limitations & Scientific Risks Audit

**Date of Audit:** November 8, 2026  
**Auditor:** Google Antigravity Research Engineering & Scientific Software Audit  
**Status:** VERIFIED via Codebase Inspection and Benchmark Metadata

## 1. Methodological & Scientific Limitations

### 1.1 Preprocessing Before Cross-Validation
- **Finding:** In the historical PhysioNet V1 benchmark (`091e47dc`), continuous raw EEG data underwent bandpass filtering (8–30 Hz) and epoch extraction across all runs *prior* to cross-validation partitioning.
- **Scientific Implications:**
  - While bandpass filtering on continuous raw data without labels does not inject label information into features, filtering continuous signals across run boundaries can introduce slight temporal leakage between adjacent epochs across run boundaries if runs were concatenated without resetting filter state.
  - Trial rejection was applied label-blind with a fixed amplitude threshold (200 $\mu$V) across all epochs.
  - **Crucial Distinction:** This operation must not be described as "fully fold-nested preprocessing." It represents label-independent continuous signal preparation. All future publications and reports must explicitly document this distinction.

### 1.2 Historical Benchmark Version Discrepancy
- **Finding:** `benchmark_results/physionet_v1/leakcheck_summary.json` records that the benchmark was executed with `emi` version `0.1.0`. The current codebase version in `src/emi/__init__.py` is `1.0.0` (and `1.1.0` for stabilization).
- **Scientific Implications:**
  - Historical benchmark artifacts (`leakcheck_raw.csv`, `inflation_table.csv`, figures) cannot be claimed to have been generated by the current software release.
  - Historical results must remain permanently isolated in `benchmark_results/physionet_v1/`. Any rerun or extension benchmark must be written to a distinct directory (e.g., `benchmark_results/physionet_v1_1/`).

### 1.3 Missing D1s vs D3 Empirical Benchmark Evaluation
- **Finding:** The historical V1 benchmark evaluated only three designs:
  1. `D3_loro` (Leave-one-run-out)
  2. `D1m_matched_k` (Random split matching fold count $K$)
  3. `P1_csp_on_all` (Global CSP contamination)
- **Scientific Issue:** While `D1m` matches the number of folds, it does not guarantee that the training set size, test set size, and class distributions match each fold of LORO. `D1s_size_matched` was implemented in `src/emi/splitters.py`, but was **never run** in the historical 105-subject benchmark.
- **Remediation Priority:** Evaluating D1s vs D3 is the primary missing scientific comparison required for the V1.1 stabilization milestone.

### 1.4 Preregistration Status
- **Finding:** Inspection of `docs/PREREGISTRATION.md` reveals that several fields remain unpopulated template text.
- **Scientific Rule:** The project **must not** claim that the historical V1 study was prospectively preregistered. For all V1.1 and V2 experiments, a formal analysis plan must be completed, dated, and version-controlled prior to executing full benchmark runs.

### 1.5 Null Model Assumptions and Caveats
- **Permutation Null:** Assumes trials are exchangeable under the null hypothesis of no relationship between EEG features and class labels. Within-run permutation correctly preserves per-run marginal class distributions.
- **Circular Shift Null:** Assumes label sequences are cyclically stationary. However, as demonstrated in `tests/test_decode_loro.py::test_shift_null_is_degenerate_for_strictly_alternating_labels`, for experimental protocols where trials alternate strictly between left and right (e.g., $L, R, L, R, \dots$), odd circular shifts produce 100% label inversion and even shifts produce 100% label identity.
- **Reporting Requirement:** Permutation and circular shift empirical p-values must always be reported separately and never merged into an arbitrary composite metric.

## 2. Software & Implementation Limitations

### 2.1 Critical Syntax Error in `src/emi/preprocess.py`
- **Location:** `src/emi/preprocess.py`, lines 72–78 in `LeakCheck_remote`.
- **Nature of Error:** `IndentationError` inside `_reject()` function following an incomplete edit of `if cfg.reject_window == "full":`.
- **Severity:** **HIGH / BLOCKER**. While cached npz tests passed, any call to preprocess raw EDF/FIF data throws a fatal Python exception.
- **Remediation:** Restore proper 4-space indentation and add unit tests specifically exercising `build_epochs_full` and `_reject`.

### 2.2 Incomplete Multi-Dataset Integration
- **OpenBMI:** 39 session-1 `.mat` files are present in `data/OpenBMI/sourcedata/session1/` (20.55 GB), but 5 subject downloads failed, and no BIDS-derivative `.npz` cache has been built or verified for OpenBMI.
- **Other Proposed Datasets:** Datasets listed in research roadmaps (Cho2017, Yang2025, BNCI2014-001, BNCI2014-004, High-Gamma) are **not downloaded** on this system.
- **Integrity Rule:** No claims of multi-dataset verification may be made until real data adapters are built, files downloaded from official repositories, checksums verified, and cache files constructed.

### 2.3 Conflation of P4 and P8
- **Finding:** In `src/emi/leakcheck.py`, `p4_channel_select_on_all` utilizes a `ChannelSelector` to pick top EEG channels based on class correlation. The roadmap occasionally refers to P4 as "Feature Selection" and P8 as "Channel Selection".
- **Remediation:** Establish a strict, non-overlapping taxonomy where P4 is reserved for spectral/temporal feature selection and P8 is reserved for spatial channel selection.

### 2.4 Decoder Scope Limitation
- **Finding:** Historical V1 results are restricted to CSP-LDA.
- **Scientific Implication:** Findings regarding leakage magnitude may be decoder-dependent. Non-linear models (CSP-SVM), regularized models (CSP-Logistic Regression), and geometry-aware models (Riemannian Minimum Distance to Mean) must be evaluated in V2 before generalizing claims across machine learning architectures.
